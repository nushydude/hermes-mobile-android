# Full-screen hands-free conversation

18 November 2026, Australia/Sydney. **Agreed; implementation authorized and in progress.** Baseline `1df5ee3`; branch `codex/fullscreen-handsfree`. The owner approved the revised multimodal preview and requested implementation, independent GPT-6.1 Sol / Extra High review, remediation, then **owner approval before commit/APK build**. Installation is a later separately authorized step when the phone is connected.

## Outcome and design contract

Replace the crowded voice sheet with a full-screen conversation experience. The existing image/camera controls, canonical shared sessions, drafts/outbox, model policy, approvals and Desktop handoff remain supported. The previous design mixed manual dictation, diagnostics, output settings and hands-free entry. Its microphone visualization displayed raw levels, so ordinary background loudness looked like speech activity. A moving meter alone is not evidence that VAD accepted noise as speech.

Revision: **handsfree-v2, multimodal**. The approved editable source and directly openable preview are [here](../designs/handsfree-v2/preview.html); [source](../designs/handsfree-v2/preview.fragment.html), [design notes](../designs/handsfree-v2/DESIGN.md). Use this same revision for implementation and review. The prototype is synthetic: it does not record, upload, create real sessions, or call a model. Its image/camera actions demonstrate a sample attachment. Standalone icon fallbacks differ from native Ionicons; use the appropriate actual native icons. Host-only design tweaks are optional; core interactions work without them.

- An icon-only waveform control beside the normal composer opens full-screen hands-free and starts listening after permission/readiness checks. No separate mode chooser, Review first or second Start action. Gboard remains the ordinary dictation path. Existing explicit message read-aloud remains available without requiring recording.
- Hands-free replies are spoken by default. Entering voice does not change the preference for reading typed replies. Remove the permanent Speak replies row from chat/voice. Put the optional typed-readback preference in settings with a specific label. Default-off timing collection and copy/export belong under troubleshooting, with a plain explanation; no diagnostic controls in the live voice screen.
- Preserve Warm Forest styling, safe areas and at least 48dp action targets. A calm orb and clear text distinguish calibration/listening, confirmed speech, processing/waiting, speaking and paused. Respect reduced motion. Do not show invented live transcript, progress percentage, total audio duration or guaranteed response time.
- Use a calibrated, smoothed **speech activity** visualization, with a quiet baseline; do not map raw microphone dB directly to a visible 20–30% floor. Test the actual detector separately from the animation. Do not claim fan/keyboard/TV rejection or microphone interruption safety until hardware acceptance establishes it.
- Pause/Resume is the primary control. Tapping the speaking orb may interrupt local output and start capture only after playback is flushed and capture is ready. This is a tap gesture, not acoustic full-duplex barge-in.
- End and Android Back require explicit confirmation, with local audio paused before showing it. No backdrop tap or swipe dismisses the room. Explicit Keep talking/Resume may resume; passive dismissal never restarts capture. Ending local voice does not stop an accepted Hermes turn or child task.
- App background/lock stops local recording/playback immediately but preserves the room in paused state on return. No background microphone. A session/endpoint change invalidates the previous room and all late callbacks. Approval/clarification, secure input, lost connection, replay gaps and uncertain delivery pause safely with a useful recovery action.
- A + control remains in both normal chat and hands-free. It opens image/camera actions after pausing local voice. Keep the room through native picker background/foreground transitions. Retain selected media, allow review/remove and require explicit Send. Do not automatically attach unrelated typed-draft images to a voice prompt. Existing support is images/camera, not a promise of general PDF/office-file support.
- A new-conversation icon inside hands-free confirms the transition, keeps the old chat/work/drafts, creates one new session and starts the new voice room without a text-chat detour. New-chat entry also offers direct voice start with chosen/default workspace and policy. Only start capture after the canonical session is known. Use single-flight admission and conservative handling of unknown creation; never automatically repeat a potentially successful create.

## Implementation and ownership

Main orchestrates using the installed `orchestrate` workflow and owns design persistence, integration acceptance, documentation and the approval handoff. One Terra 6.1/high implementor owns app UI/controller/entry/media helpers and tests; no concurrent writers to those modules. A Sol 6.1/xhigh architect investigates the narrow cross-session microphone/audio-mode and session-creation interfaces read-only. A separate Sol 6.1/xhigh reviewer receives actual code/tests and the same design revision, with actual images supplied in context, and makes zero tool calls. Main runs deterministic checks and owns remediation integration. These roles do not change Hermes's own model/profile configuration.

Likely affected areas: `VoiceSheet.tsx` or a replacement full-screen component; `voiceController.ts`, `voicePlaybackNative.ts`, `speechOwner.ts` and lifecycle helpers; ChatScreen composer/readback/media wiring; HomeScreen settings/new-chat entry; a bounded runtime voice-entry intent; narrowly scoped AppManager session-create receipt handling if necessary. Preserve the existing durable submission/correlation implementation instead of replacing it wholesale.

Resolve the audio handoff before lifecycle edits: current controller cleanup is asynchronous, and a canceled native audio-mode call can still complete. Both recording and playback need an ownership-aware serialized mode barrier, and new-room entry must await old capture teardown. Session creation must distinguish a known successful create followed by open/refresh failure from an unknown create; retain the known ID rather than issuing a new request on Retry. The architect's source findings and final selected interfaces will be recorded in the execution ledger.

No new dependencies, providers, billing, accounts or inference are needed for this scope. Preserve all Hermes/Home Dashboard configuration, profiles, MCP grants, scheduler, Serve mappings, credentials and signing identity. Native duplex/streaming APIs remain gated as recorded in the prior plan. No gateway restart or live model/audio benchmark is authorized for implementation verification.

## Acceptance and verification

1. One tap enters the correct existing/new canonical voice session exactly once, including rapid taps, permission rejection, unknown create/open failure, navigation and A→B→A endpoint/session races.
2. Old recorder preparation/cleanup and native mode completion cannot start/stop or retune a newer room; stop/interrupt releases current and prefetched playback before capture. Test callbacks at permission, mode setup, native prepare, transcription, send and playback boundaries.
3. Background, picker return and system Back preserve the intended paused/protected state; there is no passive rearm or accidental close. Pending accepted work is never resubmitted/canceled by local UI operations.
4. Camera/images stay available in both modes. Cancel/failure/stale result preserves existing draft text/images; explicit media send is correlated once, with separate pending voice media and no accidental consumption of typed drafts. Starting a new session preserves the old draft.
5. Quiet/background baseline and transient-spike tests distinguish visualization from VAD. Sustained speech and pause detection remain bounded; missing/stale metering pauses safely. Pixel acoustic acceptance is still required.
6. Check primary actions at narrow width and large text, actual icon labels/touch targets, reduced motion, truthful states and the absence of Talk text/diagnostic/main Speak rows. Native calls, Bluetooth and TalkBack remain owner phone checks.
7. Main runs relevant focused suites, the complete offline aggregate, workspace strict types, contract drift, whitespace and an Android JavaScript export/bundle check. No APK build or install before owner approval. After approval, build the versioned preview, verify source/signature/manifest/ABI/font/credential absence and prepare installation when the owner connects the phone.

Finish this implementation turn with a frozen source candidate, independent review and resolved findings, actual evidence and known hardware limits. Ask for approval of that concrete candidate before commit/APK packaging. No additional planning approval is required; the owner already approved this design and implementation.

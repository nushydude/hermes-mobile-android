# Background task projection

The task tray shows child handles observed in the current origin and parent conversation. It does not create or dispatch work. The gateway's `subagent.list` is a live roster, not a durable inventory: a successful empty list does not mean an earlier child succeeded. Previously observed live children missing from a successful roster become Unknown; a failed read leaves the previous projection intact. Only an explicit status establishes Complete, Failed or Interrupted. Unrecognized outcomes remain Unknown. The local cache retains at most 20 sessions and 50 observed children per session; cache writes are best effort and cache initialization failure leaves an in-memory projection.

Selecting a child reads its stored transcript using `session.transcript` with the parent `session_id`, `subagent_id`, `order: 'latest'`, and a bounded `limit`. An unavailable transcript does not establish the outcome. The parent remains the active conversation. Stop sends `subagent.interrupt` for that specific parent and child after confirmation. `found: true` means the request was made, not that the child stopped; a later observed terminal event may still report completion or failure.

Integration must scope persistence, results, errors and asynchronous callbacks to the connection origin and parent session, and invalidate stale responses when either changes. The projection stores only bounded observed identity and status/summary, not a complete task history; access to stored child transcripts remains subject to the gateway's ancestry check. Deduplicate terminal notifications by observed child identity across replays, and do not export task contents or identifiers to diagnostics. No continuous background execution or discovery of unobserved historical children is promised.

The source contract and an authenticated read-only empty-roster/fake-child fixture were checked before implementation. No real child was dispatched and no inference, phone, or background-lifecycle behavior was tested by that fixture.
